# 非エンジニアが Claude Code と一緒に、日本酒37万件のレビューを分析した話

## はじめに

日本酒のレビューサイトを眺めていたら、あるYouTuberが「ランキング上位は甘旨ジューシーなものばかり」と言っていた。直感的にはそうかもしれない。でも、本当にそうなのだろうか。

そう思ったのが数週間ほど前。気がつくと私は、5,386銘柄・約37万件のレビューをスクレイピングし、国立国会図書館の出版物データとGoogle Trendsまでつなぎ合わせて、140年分の味わいトレンドを分析した記事をNoteに公開していた。

（※分析の本体記事はこちら：「"辛口がいい酒"の時代は終わったのか？― 140年分のデータをつないで見えた、日本酒トレンドの現在地」←リンク）

普段は Python を書かない。統計も正直得意ではない。それでもここまで来られたのは、Claude Code というツールとずっと対話しながら進めたからだった。この記事は、その体験のまとめである。

正直に言うと、始める前は「軽くグラフを1枚2枚作って終わり」くらいのつもりだった。それがここまで膨らんだのは、Claude Code と対話しているうちに、次々に「じゃあこれも見てみたい」が湧いてきたからだ。専門知識が足りなくても、好奇心があれば掘り進められる。その感覚がとても新鮮だったので、技術的な自慢話ではなく、あくまで体験として書き残しておきたい。

## 発端：YouTube動画を見た日

きっかけは、ある日観た日本酒紹介のYouTube動画だった。「SAKETIMEというレビューサイトのランキング上位を見ると、甘旨ジューシー系の酒ばかりだ」という趣旨の話で、出てくる銘柄は十四代、新政、而今、花陽浴、いずれも日本酒好きなら知っている人気銘柄ばかり。

言われてみれば確かにそうかもしれない。ただ、私の中で少しひっかかるものがあった。「日本酒は辛口に限る」という言い回しを、昔は居酒屋でよく聞いた気がする。それが、いつの間にか甘口・フルーティの時代になったのだろうか。そもそも、ランキング上位の数十銘柄だけを見て「日本酒全体のトレンド」と言ってよいのだろうか。

漠然とした違和感のまま、Claude Code のターミナルを開いた。普段は仕事でちょっとしたコードを書いてもらうくらいの使い方をしているのだが、この日は違った。「日本酒のランキングサイトをスクレイピングして、上位の銘柄が本当に甘口なのかデータで調べたい」と、かなり雑に相談してみた。

面白いのはここからで、Claude Code は「いいですね、どのサイトにしますか？」と返してきた。「SAKETIMEです」と答えると、すぐにサイトの構造を調べ始めた。ランキングページはどうなっているか、銘柄の詳細ページは別にあるのか、レビューは1銘柄あたり何件あるのか。こちらが「こういうデータが欲しい」と伝えるだけで、情報を集めて、取得方針を整理して、「この方針でよければスクリプトを書きます」と提案してくる。

何も決めていないところから対話だけで進んでいく、この入り口の気軽さが、最後まで走り切れた一番の要因だった気がする。

## スクレイピング：対話しながら組み上げていく

実際のスクレイピング作業は、想像していたより規模が大きくなった。SAKETIMEのランキングには約5,400銘柄があり、レビューは全部で37万件以上。単純に計算しても、全部取得するのに数時間はかかる。しかも、途中でエラーが出て止まったらどうするのかとか、同じ銘柄を二重取得しないようにするにはとか、考えるべきことが結構ある。

Claude Code はそのあたりを先回りして組み込んでくれた。ランキング用、銘柄詳細用、レビュー用の3種類のスクレイパーを書き、それぞれに「どこまで取得済みか」を記録する仕組みを入れて、途中で止まっても再開できるようにした。私は「全部取ってください」と言っただけで、堅牢な運用設計まで一緒についてきた。

実行が始まると、ターミナルに進捗がずらずら流れていく。これが数時間続く。さすがに途中で重く感じたので、別のことをしていたら、サーバーから403エラー（アクセス拒否）が返ってくるようになった。同じIPから大量にアクセスしたことで、一時的にブロックされたらしい。

ここで Claude Code が、私にとって一番印象的なことを言ってくれた。

> 「SAKETIMEさんにデータ利用の許可を取った方がいいかもしれません。スクレイピング自体は技術的に可能でも、運営に一言連絡を入れて許可をいただくのが礼儀です。事後でも構わないので、連絡することをおすすめします」

正直、そこまで気が回っていなかった。ネット上の公開情報だから自由に取れる、くらいの感覚でいたのだ。指摘されてハッとして、すぐに「連絡文を書いてもらえますか」とお願いした。Claude Code は、事情を正直に伝えつつ、分析の目的と、ブログ記事での出典明記の意思、データ削除の用意があることを書き添えた、きちんとした依頼文を作ってくれた。

その文面を問い合わせフォームから送ったところ、SAKETIMEさんから丁寧なお返事をいただき、分析利用とブログ公開の許可を得ることができた。もしあのとき Claude Code が指摘してくれなければ、私は無断で記事を公開していたかもしれない。技術的なサポートだけでなく、こういう「社会的な振る舞いへの助言」をしてくれるのは、思っていた以上にありがたかった。

その後、スクレイピングは問題なく完走し、手元には約130MBの日本酒レビューデータが残った。

## データを広げる：API・出版物・検索データの統合

SAKETIMEのデータが集まった時点で、一度は「これで分析できる」と思った。ところが、実際に触り始めると、すぐに物足りなくなった。

SAKETIMEのレビューは2017年ごろから現在までしか遡れない。つまり「今のトレンド」は見えても、「今が過去と比べてどうなのか」が見えない。「辛口の時代は終わったのか」という問いに答えるには、もっと長いスパンが必要なのだ。

そう相談したところ、Claude Code は別のデータソースを提案してきた。

ひとつめは、**さけのわAPI**。日本酒コミュニティアプリが公開しているもので、約3,100銘柄について、フレーバーチャート（華やか／芳醇／重厚／穏やか／軽快／ドライの6軸数値）やフレーバータグ（141種類）が取得できる。SAKETIMEのデータが愛好家のレビューに偏っているかもしれないので、別ソースでクロスチェックするのに使える、とのこと。

ふたつめは、**国立国会図書館のNDL Ngram Viewer**。図書・雑誌約230万点のOCRテキストから、特定のキーワードの出現頻度を年代別に可視化できる。これを使えば、「辛口」「甘口」「淡麗」「芳醇」「吟醸」といった言葉が、明治時代から2000年代までどう移り変わってきたかを追える。日本酒に限定されないので解釈には注意が必要だが、長期トレンドの補助線としては強力だ。

みっつめは、**Google Trends**。2004年以降の検索キーワードの人気度がわかる。「日本酒 辛口」と「日本酒 甘口」を比較することで、一般消費者がどんな言葉で日本酒を探しているかが見える。

私は存在すら知らなかったデータソースもあった。正直、「そんなAPIがあるんですか」と感心しながら聞いていた。Claude Code はAPIを叩いてJSONを保存し、表記揺れを正規化し、SAKETIMEのデータと名寄せして、統合マスタを作ってくれた。

こうして、次の4つが手元に揃った。

- SAKETIME：2017〜2025年の愛好家レビュー37万件
- さけのわ：フレーバーの構造化データ約3,100銘柄
- NDL Ngram Viewer：1880〜2000年の出版物の語彙頻度
- Google Trends：2004〜2025年の検索トレンド

これで、約140年のスパンで日本酒の味わいトレンドを追える土台ができた。一人で「こういうデータが欲しい」と悩んでいたら、絶対にこの組み合わせには辿り着けなかった。

## 探索的データ分析：Jupyter Notebookで問いを深める

データが揃ったら、分析の段階に入る。ここで活躍したのが Jupyter Notebook というツールだった。コードとグラフとメモを一つのファイルで行き来できる、データ分析では定番の環境だ。

最初の問いはシンプルだった。「ランキング上位は本当に甘口なのか」。Claude Code は SAKETIMEの「甘辛」評価（辛い+2〜甘い+2の5段階）をランキング帯別に集計し、棒グラフにしてくれた。

結果を見て、まず一つ驚いた。**ランキングTop10の甘口率は67.3%、501位以降は27.6%**。実に40ポイントもの差があった。甘口、というYouTuberの主張は正しい。

ところがその次に「芳醇はどうですか？」と聞いたら、想定とは逆の結果が出てきた。**Top10の濃醇率（重い酒の割合）は11.2%、下位になるほどむしろ高くなる**。つまり、上位銘柄は甘口ではあるけれど、ボディは重厚ではなく、むしろ軽い方なのだ。「甘旨ジューシー」の「旨」や「ジューシー」には、ちょっと慎重になる必要があるかもしれない。

こうやって問いを出して、結果を見て、「じゃあ次はこれも見てみよう」と続けていく。このサイクルが、一人で黙々とやるのとは全然違う感覚だった。Claude Code は前の集計を覚えていてくれて、「前回Top10で取ったデータを、今度は時系列で見てみましょうか」と提案してくれる。問いが問いを呼んで、気がつくと数十種類のグラフを作っていた。

時系列で見ると、また別の景色が現れた。**2017年から2022年にかけては甘口率がやや下がり、辛口率は2022年の18%を底に、2023年以降20%台へ反転上昇していた**。「甘口が王道になった」という単純な話ではなく、どうやら辛口にも復権の兆しがある。

そして一番驚いたのが、Google Trends のデータだった。愛好家のレビューサイトでは甘口・フルーティが上位を占めているのに、**一般消費者が Google で日本酒を検索するときは、今でも「日本酒 辛口」が「日本酒 甘口」の約2.5倍**。しかも辛口の検索量は2004年から右肩上がりで増え続けている。

愛好家コミュニティの評価と、一般消費者の検索行動で、景色がこれほど違うとは予想していなかった。データを集めなければ絶対に気づけなかった事実だ。

## 結論が揺れ動く楽しさ

実はこの分析、結論が一度では決まらなかった。分析を進めるたびに、それまでの結論がどんどん書き換わっていった。

最初の結論は「ランキング上位は甘口で芳醇」だった。これはYouTube動画の主張をそのまま検証しようとしていた段階。

すぐに「甘口は正しいけど芳醇は違う」に変わった。構造化データを見た時点で、ボディは上位ほど軽い、という意外な事実が出てきた。

次に「上位と下位で二つの世界がある」という話になった。501位以降のデータを見たら、甘口率28%・辛口率29%と拮抗していて、上位（甘口率67%・辛口率4%）とはまったく違う景色が広がっていたのだ。

そこに Google Trends が加わって、「三つの層がある」に発展した。愛好家の上位銘柄、愛好家の下位銘柄、一般消費者の検索行動で、それぞれ違う言葉が主流になっている。

最終的な答えは「辛口の時代は終わっていない。むしろしぶとく生き残っている」になった。上位ランキングだけを見れば「終わったように見える」けれど、裾野を見ると辛口の銘柄は数多く存在するし、一般消費者はむしろ辛口という言葉で酒を探している。

この、結論が揺れ動くプロセスこそが、データ分析の一番面白いところだったと思う。自分が持っていた仮説が、データに裏切られ、でも裏切られるたびに現実がより立体的に見えてくる。

Claude Code が良かったのは、この試行錯誤の過程をずっと覚えていてくれることだった。「前に『甘口で芳醇』と言っていましたが、データを見直すと違いそうです」と、過去の会話を踏まえて議論を積み上げてくれる。一人で思いつきでこねくり回していたら、たぶん最初の結論のまま記事を書いていたと思う。

## 並行作業とドラフト執筆

もう一つ、Claude Code と相性がよかったのが、重い処理の並行実行だ。

37万件のレビューを取得するスクレイピングは、どうしても数時間かかる。1秒ずつ間隔を空けて取得するので、数万回のリクエストで半日近い時間がかかることもある。

普通ならその間、ただ待つしかない。でも Claude Code では、バックグラウンドでスクレイピングを回しながら、別の作業を進められる。「スクレイピングを走らせておいてください。進捗は3分おきに確認してください。その間に、先に集まったランキングデータで探索的分析を始めましょう」といったお願いが普通にできる。

実際、スクレイピングが完了する前から、取得済みの部分データで試しに集計を始めていた。仮の結論が見えて、「この方向でいけそうだ」と分かったので、記事の構成案を作り始めた。さらに、文章のドラフトまで Claude Code が書いてくれて、気がつくと Word文書（.docx）のファイルができていた。

つまり、**データ取得・分析・執筆が一つの会話のなかでシームレスに繋がっていた**。これは普段の仕事の進め方とは全然違う感覚だった。いつも「データを取る作業」「分析する作業」「書く作業」は頭の中で別のモードなのに、ここではずっと同じ対話が続いていく。

記事の文章を手で直したあと、「この修正を次回の生成でも反映できるようにスクリプトに書き戻してください」とお願いしたら、差分を取って、生成スクリプトを更新してくれた。手で直した内容が失われずに、再生成しても同じ結果が得られる。こういう地味な作業まで面倒を見てくれるのは、とてもありがたかった。

## やってみて感じた「Claude Code × データ分析」の相性

全部終わってみて、Claude Code とデータ分析は相性がすごく良い、と強く感じた。いくつか具体的に挙げたい。

**ひとつめは、自然言語でスクレイピング方針を相談できること**。普通、データ分析を始めるには「どのサイトから、何を、どうやって取るか」を自分で設計する必要がある。でも Claude Code には「日本酒ランキングのデータが欲しい」と伝えるだけでいい。あとは対話しながら、サイト構造を調べ、取得範囲を決め、スクリプトを書き、エラーが出れば直してくれる。自分で最初から全部設計しなくていい、という心理的ハードルの低さが大きかった。

**ふたつめは、Notebook・スクリプト・記事を横断して編集できること**。データ分析のコードと、生成されたグラフと、ブログ記事のWord文書が、同じ会話の中で自然に繋がっていく。「このグラフをもう少し大きく」「この数字を記事に反映して」「あの結論を更新して」といった指示が、ひとつの流れで通る。ツールを何度も切り替えなくていいので、思考の断絶が少ない。

**みっつめは、対話の連続性で問いを深められること**。前述した通り、結論は何度も書き換わった。そのたびに Claude Code は「前はこう言っていましたが、今回のデータではこう見えます」と、過去の議論を踏まえて答えてくれる。これが、ただのツールではなく「一緒に考えてくれる相手」のように感じられる大きな理由だった。自分の思考を外化して、フィードバックをもらう。そのループが早く回る。

**よっつめは、非エンジニアでも「やってみる→詰まる→対話で解決」のサイクルが回ること**。私は Python の細かい文法は知らないし、matplotlib のフォント設定なんて調べたこともない。でも、詰まったら「こうしたい」と伝えれば解決策を提示してくれる。エラーメッセージをそのまま貼れば原因を特定してくれる。知識の不足が止まる理由にならない、というのは、想像以上に大きな違いだった。

もちろん、完全に Claude Code 任せだったわけではない。「どのデータを信じるか」「どう解釈するか」「どのストーリーで記事を書くか」は、結局は自分で決める必要があった。分析の節目ごとに「ここで何を問うべきか」を考えるのは、人間の仕事だった。Claude Code は優秀な伴走者だが、走る方向を決めるのはこちらだ。

ただ、一人で走っていたら絶対に辿り着かなかった場所まで、一緒に連れて行ってくれる相棒であることは間違いない。

## おわりに

この記事で書きたかったのは、「専門知識が足りなくても、好奇心さえあればデータ分析ができる時代になった」ということだ。

始めた時点で私が持っていたのは、YouTube動画を観て感じたちょっとした違和感と、「これ調べてみたいな」という気持ちだけだった。それが Claude Code との対話を通じて、結果的に数週間がかりのプロジェクトになり、独立した分析記事一本として世に出ることになった。

途中で何度も「これ以上は専門外だな」と感じる瞬間があった。データの正規化、名寄せ、統計処理、可視化、文章執筆。普通ならそれぞれに専門家が必要な領域だ。でも Claude Code と対話しながらだと、それらを横串で貫いていける。

次にやってみたいことは、このデータを使ったレコメンデーションツールの構築だ。ユーザーが好みのキーワードを選ぶと、知名度別に日本酒を提案してくれる仕組み。これも一人で考えていたら二の足を踏むが、Claude Code がいれば「まず手を動かしてみよう」と思える。

Claude Code がすごいツールなのはもちろんなのだが、それ以上に、このツールによって「素人が気になったことを本気で掘り下げられる時代」になったこと自体が面白い。技術の民主化、というと少し大げさだが、個人の好奇心の射程が広がる感覚は、確かにあった。

もしあなたが、「ちょっと気になっているけど、調べるには技術が足りない」と思っていることがあるなら、試しに Claude Code に相談してみてほしい。意外と遠くまで連れて行ってくれるはずだ。
